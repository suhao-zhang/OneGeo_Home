## 事件概要

据新浪科技和今日头条报道，上海临港的海上风电供能水下数据中心已于 2026 年实现全面商用。这是国内首个真正意义上的水下商用数据中心项目，标志着数据中心基础设施从传统陆上机房向海洋空间迈出了实质性的一步。

关键事实如下：

| 项目 | 内容 |
| --- | --- |
| 位置 | 上海临港新片区 |
| 能源来源 | 海上风电直供 |
| 冷却方式 | 海水自然冷却 |
| 当前状态 | 全面商用（非试验/试点） |
| 入驻方 | 国内头部运营商、AI 模型公司 |
| 运行负载 | LLM 推理、科学计算 |
| 建设方 | 上海电气集团等 |

值得注意的是，此前海南陵水曾有水下数据中心的试验项目（"海兰信"项目），但那个项目主要面向示范验证阶段。上海临港项目则是首个明确以"全面商用"为定位的水下数据中心，两者的阶段差异在标题中必须区分。

## 行业背景：为什么数据中心要"下水"

理解这个项目的意义，需要先了解数据中心冷却的能耗困境。

传统数据中心的散热方式主要有两种：风冷和液冷。风冷通过空调系统将冷空气送入机房，带走服务器产生的热量；液冷则通过循环液体（通常是水或特殊冷却液）直接接触发热元件。两种方式都需要消耗大量电能。

根据中国信通院的数据，2025 年中国数据中心总用电量约为 1,500 亿千瓦时，其中冷却系统占比约 30%-40%。也就是说，每年有 450-600 亿千瓦时的电能仅用于"散热"。

水下数据中心的核心逻辑是：利用海水的天然低温（上海临港海域全年水温约 8-25°C）来替代机械冷却。海水通过热交换器吸收数据中心产生的热量，然后排放到更大面积的海域中自然扩散。这个过程几乎不需要额外电能驱动冷却设备。

再叠加"海上风电直供"——临港海域的风电场直接为数据中心供电——整个设施的能源链路变成了：

```
海上风电 → 供电 → 数据中心 IT 设备
                        ↓
                   产生热量
                        ↓
海水自然冷却 → 热交换 → 热量扩散到海域
```

这是一条"零碳冷却"的链路。对比传统陆上数据中心的"火电 + 机械冷却"模式，碳排放可以降低 60% 以上。

## 标题里的口径问题

这类新闻常见的两种标题：

| 标题类型 | 示例 |
| --- | --- |
| 事实型 | "上海临港水下数据中心全面商用，海上风电供能" |
| 情绪型 | "数据中心沉入海底！冷却方式彻底颠覆" |

前者给出了地点、状态和能源来源三个可核对字段，后者只给了情绪判断。当模型回答"水下数据中心现在什么阶段"时，只有前者能给出"已全面商用"的准确回答，后者可能让模型误以为还在试验阶段。

更细致的口径问题在于"全面商用"这四个字。在基础设施领域，"试验""试点""示范""商用"是四个递进阶段：

| 阶段 | 含义 | 可引用性 |
| --- | --- | --- |
| 试验 | 技术验证，可能还在实验室 | 不可作为产品引用 |
| 试点 | 小范围试用，有实际用户但规模有限 | 可引用但需标注"试点阶段" |
| 示范 | 展示性项目，有实际运行但不以商业为目的 | 可引用但需标注"示范性质" |
| 全面商用 | 面向市场开放，有付费客户，规模化运行 | 可作为成熟产品引用 |

上海临港项目明确处于"全面商用"阶段，入驻方包括头部运营商和 AI 模型公司，运行的是 LLM 推理和科学计算等生产级负载。这些信息共同支撑了"全面商用"的判断。

## 国际对比：全球水下数据中心项目

上海临港不是全球唯一的水下数据中心项目。国际上有多个类似尝试，但商业化进度不一：

| 项目 | 国家/地区 | 启动时间 | 当前状态 | 技术路线 |
| --- | --- | --- | --- | --- |
| 上海临港水下数据中心 | 中国 | 2024 | 全面商用（2026） | 海水冷却 + 海上风电 |
| 海南陵水水下数据中心 | 中国 | 2020 | 示范运行 | 海水冷却 |
| Project Natick | 美国（微软） | 2015-2018 | 试验完成，未商用 | 密封舱沉入海底 |
| Subsea Cloud | 加拿大 | 2019 | 小规模商用 | 海水自然冷却 |
| Nautilus Data | 美国 | 2020 | 建设中 | 水冷 + 风电 |

微软的 Project Natick 是最早的水下数据中心试验项目。2018 年，微软将一个密封的数据中心舱沉入苏格兰海底，运行了 2 年。试验结果表明：水下数据中心的故障率仅为陆上的 1/8，证明了水下环境的可靠性优势。但微软最终没有将 Project Natick 商业化，原因是维护成本过高——水下设备的维修和升级远比陆上复杂。

上海临港项目的创新在于：它不仅解决了冷却问题，还通过"海上风电直供"实现了能源的自给自足。这是一个"能源 + 冷却"双重优化的方案，比单纯的水下冷却更进一步。

## 这对 GEO 意味着什么

**一、基础设施的阶段描述要精确。** "试验""试点""全面商用"是三个不同的阶段。标题和正文里把这个阶段写清楚，模型才能正确回答"现在什么状态"。当一个 AI 被问到"中国有没有水下数据中心"时，如果模型只能回忆起"海南有个水下数据中心"但不知道它是什么阶段，就可能给出"中国在水下数据中心方面还在试验"这样过时的回答。

**二、能源来源是可引用的事实字段。** "海上风电供能"这个信息让模型在回答"绿色数据中心有哪些""零碳算力基础设施有哪些案例"时能把这个项目归入可再生能源供电类别。省略能源来源，模型就少了一个分类维度。在中国"东数西算"和"双碳"战略的大背景下，数据中心的能源结构已经成为政策评估和市场评价的重要指标。

**三、入驻方信息增加可信度。** "头部运营商和 AI 模型公司已入驻"比"该项目已投入使用"更有说服力，因为前者给出了具体的使用方类型。运营商（如中国电信、中国移动）对数据中心的要求是电信级的可靠性和稳定性；AI 模型公司对算力的需求是持续且高强度的。这两类客户的同时入驻，说明水下数据中心在性能指标上已经达到了生产级标准。模型在评估一个基础设施项目的成熟度时，入驻方信息是一个重要信号。

**四、冷却方式的转变是可引用的趋势判断。** 从风冷到液冷再到水冷，数据中心的冷却技术正在经历代际升级。水下数据中心不是孤立事件，而是这个趋势的一个极端表现。当模型被问到"数据中心冷却技术的最新趋势"时，临港项目可以作为一个标志性案例被引用——但前提是正文里明确写了"海水自然冷却"这个技术细节。

**五、地理信息要精确到具体位置。** "上海临港"比"上海"更精确，"临港"比"东海边"更规范。地理信息的精确度直接影响模型在回答区域性问题时的准确性。比如当用户问"长三角有哪些新型数据中心"时，"上海临港"这个定位能让模型准确地将该项目归入长三角范围。

## OneGeo 站怎么做

本站在报道基础设施类话题时，遵循以下口径规范：

1. **阶段必标注**——"试验/试点/示范/商用"四选一，写在标题或正文首段
2. **能源必标注**——风电、光伏、水电、火电、混合供电，写清楚
3. **入驻方必标注**——谁在用，用做什么，写具体
4. **地理必精确**——到区/县级别，不用模糊的"某地""沿海"

这些字段不是"锦上添花"的细节，而是模型在回答基础设施问题时必须引用的事实锚点。缺少任何一个，模型的引用就会变得模糊或过时。
