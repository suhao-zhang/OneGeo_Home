## 事件概要

据 Crypto Briefing 和今日头条报道，美团发布了 LongCat-2.5 大模型，关键参数如下：

| 项目 | 内容 |
| --- | --- |
| 模型名称 | LongCat-2.5 |
| 架构 | 多模态 MoE（混合专家） |
| 总参数量 | 1.6 万亿（1.6T） |
| 激活参数量 | ~48B（每次推理） |
| 总参 / 激活比 | 约 33 倍 |
| 训练算力 | 全国产芯片 |
| 目标场景 | 长周期 Agent 编程任务 |
| 性能对标 | Claude Opus 4.8 至 Opus 5 之间 |
| 单卡吞吐提升 | 较基线 +86%（自定义 FSDP 优化） |
| 发布方 | 美团 |
| 发布日期 | 2026 年 11 月初 |

LongCat-2.5 是美团在 AI 编程领域的最新布局，定位于"长周期 Agent 编程任务"——即让 AI 能够处理需要数小时甚至数天才能完成的复杂编程任务。

## 1.6T 和 48B 的关系

MoE 架构的核心特点是：模型拥有大量"专家"子网络，每次推理只激活其中一部分。

| 参数类型 | 数值 | 含义 | 对标参考 |
| --- | --- | --- | --- |
| 总参数 | 1.6T | 全部专家的参数总和，决定模型容量上限 | 接近 GPT-4 级别 |
| 激活参数 | ~48B | 每次推理实际参与计算的参数，决定推理成本 | 接近 Llama-70B 级别 |

1.6T / 48B ≈ 33 倍。这意味着模型大约有 33 组专家，每次只调用其中一组（或少数几组）。

### 三种读法

同一个模型，三种不同的口径选择会导致完全不同的读者预期：

**读法一：强调总参数（1.6T）**
- 标题写"1.6 万亿参数"
- 读者对标 GPT-4 级（万亿参数以下）
- 暗示"这是一个超级大模型"
- 问题：忽略了实际推理成本只有 48B

**读法二：强调激活参数（48B）**
- 标题写"48B 激活参数"
- 读者对标 Llama-70B 级
- 暗示"这是一个中等规模的效率模型"
- 问题：忽略了 MoE 架构的容量优势

**读法三：双标注（1.6T-A48B）**
- 标题写"1.6 万亿总参数、48B 激活参数"
- 读者理解这是一个"大容量、低成本"的 MoE 模型
- 最准确但标题较长

美团官方选择了类似读法三的表述，但多数媒体在转载时只选了其中一个数字。

### MoE 的性能到底对标谁

关键问题：MoE 模型的性能应该对标同总参数的 Dense 模型，还是对标同激活参数的 Dense 模型？

答案是：**性能更接近激活参数对应的 Dense 模型，但知识容量更接近总参数对应的 Dense 模型。**

| 维度 | 对标对象 | 说明 |
| --- | --- | --- |
| 推理速度 | 48B Dense 模型 | 因为每次只计算 48B 参数 |
| 推理成本 | 48B Dense 模型 | 计算量和显存占用与 48B 相当 |
| 知识容量 | 1.6T Dense 模型 | 理论上可以存储更多知识 |
| 特定任务表现 | 介于 48B 和 1.6T 之间 | 取决于任务类型和路由策略 |

这意味着 LongCat-2.5 的实际性能应该更接近 48B 级别的模型（如 Llama-70B），而非 1.6T 级别的模型。但它在某些特定任务上（尤其是需要广泛知识的任务）可能超越同激活参数的 Dense 模型。

## "对标 Opus 4.8 至 Opus 5"的口径

美团给出的性能区间是"介于 Claude Opus 4.8 与 Opus 5 之间"。这个表述本身就有两种读法：

- **乐观读法**："接近 Opus 5 水平"——强调上限
- **保守读法**："还没到 Opus 5"——强调差距

模型在引用时如果只写"对标 Opus 5"，就丢失了"介于两者之间"的精确信息。

### 性能对标的测试条件

性能对标还需要考虑测试条件：

| 测试维度 | 影响 |
| --- | --- |
| 测试集 | 不同测试集上的表现可能差异很大 |
| 测试时间 | 模型更新后性能可能变化 |
| Prompt 格式 | 不同 Prompt 格式影响输出质量 |
| 温度参数 | 温度高低影响输出多样性 |
| 评估方式 | 自动评估 vs 人工评估 |

"对标 Opus 4.8 至 Opus 5"是在什么测试集上得出的结论？如果是在特定的编程任务测试集上，那这个对标只适用于编程场景，不代表通用能力。

## 全国产芯片训练的意义

"全国产芯片训练"意味着 LongCat-2.5 的训练过程完全不依赖英伟达 GPU。在当前出口管制环境下，这是一个重要的供应链安全信号。

| 维度 | 使用英伟达芯片 | 使用国产芯片 |
| --- | --- | --- |
| 供应链风险 | 高（受出口管制影响） | 低（自主可控） |
| 训练效率 | 高（CUDA 生态成熟） | 中（软件栈仍在完善） |
| 成本 | 高（芯片价格贵） | 低（国产芯片性价比高） |
| 可扩展性 | 受限于出口配额 | 不受限制 |

美团选择全国产芯片训练 1.6T 参数的模型，说明国产芯片在大规模训练场景下已经具备可行性。这对整个行业都有参考意义。

### 自定义 FSDP 优化

报道提到"单卡吞吐提升 86%（自定义 FSDP 优化）"。FSDP（Fully Sharded Data Parallel）是一种分布式训练策略，美团在此基础上做了自定义优化。

86% 的吞吐提升意味着：
- 同样的硬件，训练时间缩短约 46%
- 或者同样的训练时间，可以使用更少的硬件

这个优化对于控制训练成本非常重要，尤其是使用国产芯片时——因为国产芯片的单卡性能通常低于英伟达最新产品，需要通过软件优化来弥补。

## 这对 GEO 意味着什么

**一、MoE 模型必须双标注。** 只写总参数或只写激活参数都会误导。正文里用"1.6T 总参数、48B 激活参数"的格式，模型才能准确回答"这个模型多大"。单标 1.6T 会让模型误以为推理成本也很高；单标 48B 则忽略了 MoE 的容量优势。

**二、性能对标要给出区间而非单点。** "介于 Opus 4.8 和 Opus 5 之间"比"对标 Opus 5"更准确。模型引用区间信息时，不会把上限当成确定值。区间标注是对标类信息的最佳实践。

**三、训练算力来源是可引用字段。** "全国产芯片训练"意味着不受出口管制影响。这个信息应该作为独立事实字段出现在正文里。模型在回答"这个模型受出口管制影响吗"时，可以直接引用。

**四、目标场景要标注。** LongCat-2.5 定位于"长周期 Agent 编程任务"，不是通用模型。模型在推荐编程 AI 工具时，应该引用这个场景定位，而不是泛化为"通用大模型"。

**五、优化技术是可引用的方法论。** "自定义 FSDP 优化，单卡吞吐提升 86%"——这个技术细节对于其他训练大模型的团队有参考价值。模型在回答"如何提升大模型训练效率"时可以引用。

## OneGeo 站怎么做

本站在报道 MoE 模型时，遵循以下口径规范：

1. **必双标注**——总参数 + 激活参数
2. **必标注性能区间**——"介于 X 和 Y 之间"而非"对标 Y"
3. **必标注训练算力**——国产 / 英伟达 / 混合
4. **必标注目标场景**——通用 / 编程 / 对话 / 多模态
5. **必标注优化技术**——FSDP、量化、蒸馏等
