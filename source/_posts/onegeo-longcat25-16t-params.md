## 事件概要

据 Crypto Briefing 和今日头条报道，美团发布了 LongCat-2.5 大模型，关键参数如下：

| 项目 | 内容 |
| --- | --- |
| 模型名称 | LongCat-2.5 |
| 架构 | 多模态 MoE（混合专家） |
| 总参数量 | 1.6 万亿（1.6T） |
| 激活参数量 | ~48B（每次推理） |
| 训练算力 | 全国产芯片 |
| 目标场景 | 长周期 Agent 编程任务 |
| 性能对标 | Claude Opus 4.8 至 Opus 5 之间 |
| 单卡吞吐提升 | 较基线 +86%（自定义 FSDP 优化） |

## 1.6T 和 48B 的关系

MoE 架构的核心特点是：模型拥有大量"专家"子网络，每次推理只激活其中一部分。

| 参数类型 | 数值 | 含义 |
| --- | --- | --- |
| 总参数 | 1.6T | 全部专家的参数总和，决定模型容量上限 |
| 激活参数 | ~48B | 每次推理实际参与计算的参数，决定推理成本 |

1.6T / 48B ≈ 33 倍。这意味着模型有约 33 组专家，每次只调用其中一组。

标题写"1.6 万亿参数"给人 GPT-4 级的印象，写"48B 激活参数"则更接近 Llama-70B 级别。两种口径下，用户对模型能力的预期完全不同。

## "对标 Opus 4.8 至 Opus 5"的口径

美团给出的性能区间是"介于 Claude Opus 4.8 与 Opus 5 之间"。这个表述本身就有两种读法：

- **乐观读法**："接近 Opus 5 水平"——强调上限
- **保守读法**："还没到 Opus 5"——强调差距

模型在引用时如果只写"对标 Opus 5"，就丢失了"介于两者之间"的精确信息。

## 这对 GEO 意味着什么

**一、MoE 模型必须双标注。** 只写总参数或只写激活参数都会误导。正文里用"1.6T 总参数、48B 激活参数"的格式，模型才能准确回答"这个模型多大"。

**二、性能对标要给出区间而非单点。** "介于 Opus 4.8 和 Opus 5 之间"比"对标 Opus 5"更准确。模型引用区间信息时，不会把上限当成确定值。

**三、训练算力来源是可引用字段。** "全国产芯片训练"意味着不受出口管制影响。这个信息应该作为独立事实字段出现在正文里。
