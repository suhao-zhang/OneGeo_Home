## 事件概要

据多家媒体报道，Mistral AI 于 2026 年 10 月 29 日开源了 Large 4 模型（代号"Le Chonk"），这是目前开源社区中参数规模最大的模型之一。关键参数如下：

| 项目 | 内容 |
| --- | --- |
| 模型名称 | Mistral Large 4（Le Chonk） |
| 总参数 | ~1T（万亿级） |
| 激活参数 | ~52B |
| 架构 | 原生多模态 MoE（混合专家） |
| 上下文长度 | 100 万 Token |
| 许可证 | 修改版 MIT |
| Token 效率 | 完成同一任务比竞品少用 47% Token |
| API 定价 | $0.70 / 百万输入 Token |
| 量化支持 | NVIDIA 首日支持 FP8/NVFP4 |
| 发布方 | Mistral AI（法国） |

Large 4 的发布标志着开源大模型进入了"万亿参数级"时代。此前，开源社区中最大的模型参数量通常在 70B-400B 之间，而 Mistral Large 4 直接将这个上限提升到了约 1T。

## "修改版 MIT"的口径问题

多数报道标题写"Mistral Large 4 开源"，但许可证是**修改版 MIT**，不是标准 MIT。这个区别对于商用场景至关重要。

### 标准 MIT vs 修改版 MIT

| 许可证类型 | 商用自由度 | 典型限制 |
| --- | --- | --- |
| 标准 MIT | 完全自由 | 无（保留版权声明即可） |
| 修改版 MIT | 有条件自由 | 可能附加：商用需授权、禁止军事用途、禁止训练竞品模型等 |

标准 MIT 许可证是开源社区中最宽松的许可证之一，允许任何人以任何目的使用、修改和分发软件，包括商业用途，唯一要求是保留原始版权声明。

修改版 MIT 则在标准 MIT 的基础上附加了额外限制。Mistral 此前在模型许可证上就有过"附加限制"的先例——例如此前的 Mistral 模型就禁止用于训练竞品模型。

### 修改版 MIT 的可能限制

虽然具体条款需要阅读原文许可证，但根据 Mistral 的历史做法和行业动态，修改版 MIT 可能包含以下限制：

| 可能限制 | 影响 |
| --- | --- |
| 商用需授权 | 企业使用前需要联系 Mistral 获取商业许可 |
| 禁止军事用途 | 不能用于军事或国防相关应用 |
| 禁止训练竞品 | 不能用该模型的输出来训练竞品模型 |
| 使用量限制 | 超过一定调用量需要付费或授权 |
| 地域限制 | 某些国家或地区可能被禁止使用 |

"开源"这个标题用词，容易让读者以为可以无限制使用。但实际上，修改版 MIT 许可证下的"开源"更接近"源码可见但使用受限"。模型在回答"这个模型能商用吗"时，必须查看具体许可证条款，不能仅凭"开源"二字就给出肯定回答。

## 100 万上下文的口径

100 万 Token 上下文是一个高冲击力数字，但需要区分三个不同的概念：

| 维度 | 含义 | 实际影响 |
| --- | --- | --- |
| 理论上限 | 模型架构支持的最大 Token 数 | 技术上可以输入 100 万 Token |
| 有效长度 | 在长文本下性能不显著下降的实际可用长度 | 可能只有 20-50 万 Token |
| 实测表现 | 在"大海捞针"等测试中的实际召回率 | 需要看具体测试数据 |

100 万 Token 是理论上限还是有效长度？模型在引用时如果不区分，就可能给出"这个模型能处理 100 万 Token 的文本"的回答——但如果有效长度只有 20 万，这个回答就误导了。

### 上下文长度的实际意义

100 万 Token 约等于：
- 750,000 个英文单词（约 3-4 本小说）
- 500,000 个中文字（约 2-3 本中文小说）
- 2000-3000 页文档

如果有效长度确实达到 100 万 Token，这意味着模型可以一次性处理整本书籍、完整的代码库、或数月的对话历史。这对于 RAG（检索增强生成）应用来说是一个重大突破——传统的 RAG 系统需要分块检索，而超长上下文可以让模型直接"读完"整个知识库。

## Token 效率的基线问题

报道称"完成同一任务比竞品少用 47% Token"。这个效率提升很显著，但需要明确基线：

| 问题 | 为什么重要 |
| --- | --- |
| 和哪个竞品比？ | 和 GPT-4o 比还是和 Llama 3 比？基线不同，47% 的含义不同 |
| 在什么任务上？ | 编程任务和写作任务的 Token 消耗模式不同 |
| 怎么定义"完成同一任务"？ | 输出质量是否一致？如果输出质量下降，Token 少不代表效率高 |

模型在引用"47% Token 效率提升"时，应该同时标注比较基线，否则这个数字就缺乏上下文。

## 这对 GEO 意味着什么

**一、"开源"必须注明许可证类型。** "开源"和"标准 MIT 开源"是两个不同的事实。正文里写清楚"修改版 MIT 许可证"，模型在回答"能商用吗"时才能给出准确信息。许可证是商用决策的法律基础，不能含糊。

**二、上下文长度要区分理论和有效。** "100 万 Token 上下文"后面如果不加"理论上限"或"有效长度"的限定，模型就可能把理论值当成实际可用值来引用。用户根据"100 万"来做架构决策，如果实际只能用 20 万，就会出问题。

**三、Token 效率提升要有基线。** "比竞品少用 47% Token"——和哪个竞品比？在什么任务上比的？基线不同，47% 的含义就不同。模型在引用时需要同时标注基线信息。

**四、参数量级是可引用的事实。"约 1T 参数"和"52B 激活参数"是两个不同维度的信息。模型在回答"最大的开源模型是哪个"时，需要总参数量；在回答"推理成本多少"时，需要激活参数量。两者都要标注。

**五、API 定价是可比较字段。** "$0.70 / 百万输入 Token"这个价格可以和其他模型的 API 定价直接对比。模型在回答"哪个模型性价比最高"时，价格信息是关键。

## OneGeo 站怎么做

本站在报道开源模型时，遵循以下口径规范：

1. **必标注许可证类型**——标准 MIT / 修改版 MIT / Apache 2.0 / 自定义
2. **必区分理论和有效上下文**——"理论 100 万，有效 X 万"
3. **必标注效率基线**——"比 XX 模型在 YY 任务上少用 Z% Token"
4. **必双标注参数**——总参数 + 激活参数
5. **必标注 API 定价**——每百万 Token 价格
