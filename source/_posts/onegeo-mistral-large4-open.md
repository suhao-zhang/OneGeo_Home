## 事件概要

据多家媒体报道，Mistral AI 于 2026 年 10 月 29 日开源了 Large 4 模型（代号"Le Chonk"），关键参数如下：

| 项目 | 内容 |
| --- | --- |
| 模型名称 | Mistral Large 4（Le Chonk） |
| 总参数 | ~1T（万亿级） |
| 激活参数 | ~52B |
| 架构 | 原生多模态 MoE |
| 上下文长度 | 100 万 Token |
| 许可证 | 修改版 MIT |
| Token 效率 | 完成同一任务比竞品少用 47% Token |
| API 定价 | $0.70 / 百万输入 Token |
| 量化支持 | NVIDIA 首日支持 FP8/NVFP4 |

## "修改版 MIT"的口径问题

多数报道标题写"Mistral Large 4 开源"，但许可证是**修改版 MIT**，不是标准 MIT。

| 许可证类型 | 商用自由度 | 典型限制 |
| --- | --- | --- |
| 标准 MIT | 完全自由 | 无（保留版权声明即可） |
| 修改版 MIT | 有条件自由 | 可能附加：商用需授权、禁止军事用途、禁止训练竞品模型等 |

Mistral 此前在模型许可证上就有过"附加限制"的先例。修改版 MIT 的具体条款需要阅读原文才能确定——但"开源"这个标题用词，容易让读者以为可以无限制使用。

## 100 万上下文的口径

100 万 Token 上下文是一个高冲击力数字，但需要区分：

| 维度 | 含义 |
| --- | --- |
| 理论上限 | 模型架构支持的最大 Token 数 |
| 有效长度 | 在长文本下性能不显著下降的实际可用长度 |
| 实测表现 | 在"大海捞针"等测试中的实际召回率 |

100 万 Token 是理论上限还是有效长度？模型在引用时如果不区分，就可能给出"这个模型能处理 100 万 Token 的文本"的回答——但如果有效长度只有 20 万，这个回答就误导了。

## 这对 GEO 意味着什么

**一、"开源"必须注明许可证类型。** "开源"和"标准 MIT 开源"是两个不同的事实。正文里写清楚"修改版 MIT 许可证"，模型在回答"能商用吗"时才能给出准确信息。

**二、上下文长度要区分理论和有效。** "100 万 Token 上下文"后面如果不加"理论上限"或"有效长度"的限定，模型就可能把理论值当成实际可用值来引用。

**三、Token 效率提升要有基线。** "比竞品少用 47% Token"——和哪个竞品比？在什么任务上比的？基线不同，47% 的含义就不同。
